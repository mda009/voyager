CSV upload update — no new Streamer.bot action

Reporting → Upload Twitch CSV now opens a dedicated upload view. It accepts the Twitch daily analytics, viewer engagement and revenue files you have used, including dates such as Tue Aug 04 2026.

  1. Copy the updated Voyager_Command_Center.html, twitch-analytics-model.js, twitch-analytics.js and twitch-analytics.css into your working Voyager folder.
  2. Keep your existing config.js, stream-command-settings.js, stream-home-data.js and twitch-analytics-data.js. Refresh the Reporting dock/page.
  3. Click Upload Twitch CSV, either at the top of Reporting or in Your Twitch reports.
  4. Enter the time zone shown by the source report and, for revenue, its three-letter currency code. These are not inferred from your location or the amounts.
  5. Drop or choose your CSV files. Review the daily reports and any differing saved values, then click Import reports.

CSV upload works without the live chat tracker. No Streamer.bot import or C# compile is needed for this update. Results appear in Daily stream performance → Reporting window and Explore all reported metrics. The separate 30-day performance/ranking panel keeps its own source-reported figures.

2. Install the chat tracker

  1. In Streamer.bot, click Import and load Voyager_Twitch_Analytics_Install.sb. Import the one Voyager - Twitch Analytics action and Voyager Twitch Analytics queue. It contains a copy of the Chat Message trigger configuration from your supplied export.
  2. Open Voyager - Twitch Analytics. Confirm it is enabled, Concurrent is off, and its queue is Voyager Twitch Analytics. The queue must be Blocking and unpaused. Keep exactly one enabled action with this name.
  3. Confirm there is exactly one enabled trigger: Twitch → Chat → Chat Message, without user exclusions. If it is missing, right-click the Triggers area and add it. No timer trigger or command is required.
  4. Open its Execute C# Code sub-action, click Compile, then save. The import includes the existing assembly references from your supplied setup; you do not need to search Windows for DLLs. If compilation fails, send the full error text before changing references.
  5. Keep Streamer.bot’s Twitch connection and WebSocket server running. Return to Home and click Refresh chat. It should show TRACKER CONNECTED.
  6. Send an ordinary message in your Twitch chat. Within 30 seconds, the message and unique-chatter counts should appear. Send another message from the same account: messages should increase by one, and unique chatters should stay the same. A second account should increase unique chatters. This works while offline too.

This new action is independent of your Points Ledger, Community Tracker, Stream Stats and giveaway actions. Do not replace those actions or add their triggers to this one.

Signed report values

Subscription and follower changes can be negative. The importer preserves signed values in Follows, subscription totals, Tier 1/2/3, Prime, gifted subscriptions, multi-month gifts and subscription points. For example, a Tier 3 subscriptions entry of -1 stays -1. These source-reported figures are not a live subscriber headcount. The same rules apply to CSV upload, saved reports, manual edits and JSON restoration.

Negative revenue amounts and scientific notation (such as -1.25 or 2.5e-7) are accepted and kept with their original sign. Accounting parentheses such as ($1.25) mean a negative amount. Small amounts are shown without rounding them to zero. Blank cells, dashes and N/A mean unavailable; they do not erase saved values. Viewer counts and percentages still require non-negative values. Invalid cells show the filename, metric, CSV row, date and actual value; the upload is not partially saved.

How matching files are combined

  • Matching dates, title, source and time zone identify a saved report. Uploading engagement first and revenue later preserves both sets of metrics.
  • Overlapping values are never added together. Reimporting the same export does not duplicate dates or inflate totals.
  • Missing or blank cells preserve saved metrics. An explicit 0 is a reported value and can update a previous value.
  • If two selected files disagree on the same metric/date, the batch is rejected before saving. Import them separately and review which value to keep.
  • Different currencies cannot be merged into the same saved report. Use the correct source currency or a separate report title.
  • Existing audience-country/device/source breakdowns are preserved during CSV uploads. A daily analytics CSV does not create breakdowns it does not contain.

Daily unique viewers and chatters are not summed, and daily averages are not treated as whole-period averages. For an accurate 30-day unique/average figure, enter Twitch’s whole-period figure as a separate manual report. Revenue components and subscription tiers remain separate fields; this importer does not invent a total by adding potentially overlapping measures.

The supplied export columns now include Chatters, Total Paid Subs, Total Gifted Subs, gifted tiers, multi-month gifts, engaged viewers, additional revenue components and featured/unfeatured clip views. Ad Time (Seconds) Per Hour retains its seconds unit. Extra numeric columns stay under Additional metrics; text columns are kept as notes.

For manual reports, use Manage Twitch reports → New report. For a JSON backup, use Choose files and select one JSON file on its own. JSON replaces matching reports in full, as stated in its review; CSV merges available metrics. Up to 400 reports are retained.

Reporting windows

Reporting → Daily stream performance opens on Previous 30 days. Use the Reporting window menu for Previous 14 days, Previous 7 days, Latest stream or an individual saved report. The 30/14/7-day presets cover complete calendar days ending yesterday in the report time zone. Dates and coverage are shown. If the report's time zone is an informal label such as Australia, the browser time zone is used and identified. Reopening Reporting defaults to 30 days; uploading data keeps your currently selected preset.

Latest stream: uses the newest imported daily report with Minutes Streamed or Hours Streamed above zero, skipping later days marked zero. The date is displayed. Daily exports cannot distinguish multiple streams on one day or join a stream across midnight. If streaming time is absent from every report, the newest daily report is shown with a clear limitation notice.

  • Chat messages, live views, time, revenue and signed subscription/follower values are totalled across available daily reports. Each date contributes once; the canonical Twitch daily export is preferred over overlapping daily reports.
  • Peak viewers is the highest reported peak. Average viewers and ad rates are weighted by recorded streaming duration. Each metric shows its coverage or calculation.
  • Missing days or values are not filled with zero. Incomplete periods show the number of reported dates.
  • Unique viewers, unique chatters and other distinct-person counts are not added across days. Without an exact whole-period report, the cards show clearly labelled daily averages for unique viewers/chatters. Period-wide unique counts remain unavailable.
  • Country/device/discovery shares and other percentages require an exact source report for the selected dates. They are not averaged across unrelated daily percentages. Exact whole-period reports take precedence for the fields they contain.
  • Different sources, time zones or currencies are kept separate. Use the Report source selector when more than one set is available.
  • Individual reports remain selectable for historical dates, additional metrics and editing. Calculated windows are display-only; Manage Twitch reports edits an original report, never a calculated total.

The windows use your imported Twitch reports. Live audience/chat today and the separate public 30-day ranking/performance panel retain their own stated reporting periods. No Streamer.bot change is needed.

What the live counts mean

  • Current viewers is a platform-reported concurrent audience. It is separate from Live views in an analytics report.
  • Unique chatters today counts distinct Twitch account IDs that sent a captured message during the UTC day. It includes broadcaster/bot messages and offline chat. Tests and shared-chat guest messages are excluded. This is not the number of people watching the video.
  • Messages per minute is messages in the five completed UTC minute buckets before the current minute, divided by five. It excludes the current partial minute.
  • Coverage starts when the enabled action receives events. Missed messages while Streamer.bot is closed/disconnected or the queue is paused cannot be recovered. First/last captured message timestamps are displayed; they are not proof of uninterrupted collection.
  • Today's account IDs are retained for distinct counting. Message text is never stored. The most recent 10,000 message IDs suppress duplicate event deliveries. The account cap is 50,000 per UTC day; a warning marks a lower bound if exceeded. Prior-day history contains aggregate counts only, retaining up to 30 previous capture days.
  • The ledger lives in the persisted global VoyagerTwitchAnalyticsV1. Include persisted globals in Streamer.bot backups. JSON report exports contain imported reports only, not the native chat ledger.
