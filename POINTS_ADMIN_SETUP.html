4. Add or deduct points for one person

  1. Click Manage a member, or the Manage button beside a member in the table.
  2. Search for and select the correct account. The platform and stable user ID are shown. For a Twitch user not yet listed, enter their Twitch login in the lookup field. For YouTube and Kick, select a tracked account; Refresh after it first appears in your existing currency or group system.
  3. Choose Adjust points, then Add or Deduct and a positive whole amount.
  4. Enter a reason, click Preview changes, and check the name, platform and before/after balance.
  5. Tick the review checkbox and click Apply changes. Wait for the verified result.

Adjustments use your configured persisted points variable and increment it by the signed amount. An unavailable or fractional balance, an overdraft, a stale balance, or a value outside the supported range is rejected. A missing variable must first be initialized by your existing currency action; the control does not assume it is zero. Individual edits exclude the three giveaway bucket accounts.

The History tab includes administrator requests/results with your reason. The normal native variable listener records the numeric movement once and labels a matching write as Administrator adjustment. Manual credits are not counted as earned rewards or !upgrade purchases. With the balance listener disabled, the receipt remains but numeric movement totals may be incomplete.

5. Add or remove a member from a group

In Manage a member, choose Add to a group or Remove from a group, select Blue, Silver, Gold, Platinum or VIP, enter a reason and preview. This changes only the selected group. To manually move a member, add the destination group and then remove the previous group. VIP can coexist with a core tier.

These are Streamer.bot user groups. Editing VIP GROUP does not grant or revoke a Twitch VIP badge. Existing group-triggered actions, such as any role synchronization you have installed, still run.

6. Clear a group of members

Click Choose group, select the group, enter a reason and preview its full membership. Search or page through the preview, and optionally download the list as CSV. Type the exact group name shown, tick the review checkbox and apply.

Only the members included in this preview are removed from that group, across Twitch, YouTube and Kick. The group, their points, other memberships, history and giveaway bucket balances remain. Any members added after preview are left in place. A changed member is rejected or marked for review. Existing automatic membership or VIP sync actions may add members again later.

7. Import your current Twitch subscribers

Click Import subscribers. The code uses the broadcaster account already connected to Twitch in Streamer.bot and fetches every page of the current active subscriber list. You do not copy an OAuth token into the page or config.js.

Choose how to handle existing core tiers:

  • Preserve higher Voyager tiers — default: promote members to the mapped tier, replacing lower core groups. Skip subscribers who already hold a higher Voyager tier. For example, a Tier 1 Twitch subscriber in Platinum stays in Platinum.
  • Replace core tier to match Twitch: remove that subscriber’s other Blue/Silver/Gold/Platinum memberships and place them in exactly the mapped group. A Tier 1 subscriber in Platinum would move to Blue; this is visible in the preview.

Both modes preserve VIP, Emerald and unrelated groups. They do not award or deduct points, add money to giveaway buckets, change expiry counters, or remove nonsubscribers from groups. The import is manual, not an ongoing subscriber-expiry sync.

The preview shows the number of unique accounts, Twitch’s reported total, any duplicate records combined, and whether two full reads matched. A total that differs from the account count is flagged for review. If Twitch returns multiple tiers for one account, the importer uses its highest returned tier: Tier 1 → Blue, Tier 2 → Silver, Tier 3 → Gold. Those accounts are flagged with all returned tiers in the preview and exported CSV. This is an import policy, not a claim that Twitch changed the subscription during loading. Default higher-tier protection still applies.

Check the channel name, fetched time, all proposed changes and unchanged members. Tick the review checkbox and apply. Preview plans expire after five minutes. Repeating a completed import with the same membership state produces no changes. Gift recipients are imported using their subscriber IDs; gift senders are not substituted.

If Twitch denies subscriber access, reconnect the broadcaster account in Streamer.bot and authorize subscription reading, then preview again. A network error, missing data or pagination metadata, repeated cursor, rate limit, invalid tier or unstable account/tier list stops the preview without applying changes. Twitch’s reported total is shown for comparison, but is not used as an exact count check. No page is skipped merely because the reported total has been reached. No members need to be watching or chatting for the active list to include them.

8. Change a giveaway bucket balance

On the Points page, scroll to Tier points buckets and click Edit balance on Silver, Gold or Platinum.

  1. Check the bucket and account shown.
  2. Choose Add points, Deduct points, or Set exact balance. Set an exact balance of 0 to reset that bucket.
  3. Enter the amount and a reason.
  4. Click Preview changes. Check the actual saved balance, proposed balance, signed adjustment and goal percentage.
  5. Tick the review checkbox, then click Apply changes. The page refreshes the bucket reading after the verified result.

The control changes the existing persisted points balance of that bucket account. Giveaway goal amounts, member balances, group membership and upgrade costs are unchanged. Your existing actions that watch the bucket balance can still react to a goal being reached; this control does not directly start a giveaway or an OBS animation.

The adjustment is recorded in History → Bucket movements and administrator history, with the before/after values, signed movement, reason and operation reference. View movements on the bucket opens its history. Bucket movements remain separate from member earnings and !upgrade spending. Keep the native variable listener enabled to capture the numeric movement.

A preview that becomes stale is rejected before writing. An exact balance is applied as the verified difference from the saved balance, using the existing increment operation, so a browser snapshot cannot overwrite a newer balance. Concurrent actions can still cause a result to need review; read the saved receipt before another edit. Setting the existing balance again is a no-op.

Missing or fractional saved balances and deductions below zero are rejected. Amounts and the size of any single adjustment are limited to 1,000,000,000 whole points. If Edit balance is disabled while connected, install the v4.3 ledger code and refresh. For customized configurations, BucketPointsField and the Twitch entry in PointsFields must match; both are points in your supplied setup.

To practice, open Preview_Points.html. Its bucket controls use fictional data and never connect to Streamer.bot.

Results, reconnects and history

Every confirmed operation has a unique reference and a saved receipt. Point/group writes start only after that receipt is saved. Repeating the same Apply request returns its saved result instead of applying twice. A disconnect never automatically repeats a change.

If the result is unconfirmed, use Check saved result. A page reload keeps a reminder for the last unconfirmed operation on this browser. If an operation was interrupted or has members marked for review, inspect their current balances/groups and history in Streamer.bot before starting another operation. A started request is deliberately not replayed after a crash. Once you have checked, use I have checked the current values to clear an incomplete-operation reminder.

Bulk group changes can partly succeed if another action changes membership or a write fails. The result identifies each completed member and each member needing review. Download its CSV for the full before/after plan and observed result. This is not an automatic undo: use a new, reviewed edit to correct a member.

Keep the four native listeners and two-minute timer running. Group events and point events may wait behind the admin batch on the same queue; Refresh again after it drains. Existing currency actions on other queues can still run: balance checks and native increment calls reduce stale-write risk, but this is not a transaction across all your actions. Use administration between large reward batches when possible.

Receipts are stored in the admin subfolder of %LOCALAPPDATA%\MDA009\VoyagerPoints, alongside the existing ledger archive. Back up the whole folder with Streamer.bot closed. Do not remove operation receipts to retry a change. The page should remain a private control dock; use your existing authenticated WebSocket connection.

One small check after installation

Use your own test account: add 1 point with a reason, verify the result, then make a separate 1-point deduction. History should show both movements. Verify a group add/remove on that same test account before clearing a real group. Open Preview_Points.html to practice the full interface using fictional data.

The interface and connection behavior have been tested with sample data and simulated Streamer.bot responses, including the 392-record / 388-account / 391-total mismatch. C# compilation and live point/group operations must be checked in your Windows Streamer.bot instance. No changes have been applied to your live accounts by downloading this package.
