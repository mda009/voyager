The tracker runs while Streamer.bot is running, even if the Command Centre is closed. The page reads its saved totals every 60 seconds. Other Voyager features and the original giveaway animation remain as before.

1. Copy the updated files

  1. Close the Command Centre page and OBS dock. Extract this ZIP into a temporary folder.
  2. Copy the following files into your working Voyager_Giveaway folder: Voyager_Command_Center.html, stream-command.js, stream-command-model.js, stream-leaderboards.js, stream-leaderboards.css, Voyager_Stream_Stats.cs, Voyager_Community_Tracker.cs, Voyager_Native_Community_Install.sb, NATIVE_COMMUNITY_SETUP.html and COMMAND_CENTER_SETUP.html.
  3. Keep your working config.js, stream-command-settings.js and stream-home-data.js. No connection credentials or follower goals need to change.

2. Import the two actions

  1. In Streamer.bot, open Import and select Voyager_Native_Community_Install.sb. If the dialog expects text, open that file in Notepad, copy all its contents and paste them into the import string field.
  2. The import contains Voyager - Community Tracker, a new Voyager Community blocking queue, and an update to your existing Voyager - Stream Stats. Import both actions and the queue. It uses the existing stats action ID from your supplied export; if you renamed/recreated that action since then, ensure there is only one enabled action with the configured stats name.
  3. Open Voyager - Community Tracker → Execute C# Code. Click Compile, then Save after success. Its final line is // End of Voyager Community Tracker v1.
  4. Open Voyager - Stream Stats → Execute C# Code. Click Compile, then Save after success. Its final line is // End of Voyager Stream Stats v3. Keep Get Follower Count and Get Subscriber Count above this C# sub-action.
  5. Check that Community Tracker is enabled, assigned to the unpaused Voyager Community queue, with Blocking ON and Concurrent OFF. Keep one enabled copy. Stats keeps its separate Voyager Stats queue.

The import carries the references from your supplied working Stream Stats action, including Newtonsoft.Json. It needs no Tawmae DLL. Compilation must still be checked on your streaming PC; this environment cannot compile Streamer.bot actions. If there is an error, copy the full compile-log text, including the code and line number.

The tracker reuses native trigger configurations from your existing Currency System Events action in the supplied export. It does not edit that currency action. Unrelated copied event types return immediately without changing the ledger. Check the relevant triggers below if your current setup differs from that export.

3. Set Present Viewers to one minute

  1. In Streamer.bot's Twitch account settings, find Present Viewers, set its interval to 1 minute, and turn Live Update ON. Connect your broadcaster account and allow Streamer.bot's required channel permissions.
  2. For YouTube, connect your account and monitor the intended live broadcast. For Kick, connect your channel. Their Present Viewers events run every minute from recent chat activity; they do not provide a complete list of silent video viewers.
  3. Keep Streamer.bot running during the stream. Do not attach a second timer that manually runs the tracker: a manual run has no native presence arguments.

Changing Twitch's Present Viewers interval also affects other actions listening to it. Your existing currency action uses this event, so check any fixed per-tick points award when changing the interval. This package does not change your currency rules.

The first live sample establishes a baseline. A user must appear in consecutive samples before gaining time. Offline samples, a restart, duplicate rapid triggers and gaps over 90 seconds do not add catch-up time. Use the one-minute setting; a five-minute interval will intentionally receive no time credit.

4. Select the native source

  1. Open Voyager_Live_Dashboard.html and connect to Streamer.bot.
  2. Choose Live dashboard → Community leaderboards → Leaderboard settings.
  3. Select Native Streamer.bot for Twitch, YouTube and Kick. Click Save & check. Native mode is now the default and ignores legacy user-variable mappings.
  4. Check the status under each leaderboard. While live, allow two presence samples plus up to one minute for the next page refresh. Hours use one decimal place, so a newly tracked minute may display as 0.0 before reaching 0.1.
  5. If you use both a browser and OBS dock, export the saved settings, replace stream-command-settings.js in this folder with that export, then refresh the OBS dock.

Subscription and gift rows wait for actual platform events. A connected page does not create historical data. Streamer.bot Test events marked isTest are ignored to protect real totals.

Subscriber missions and season sub goals (Voyager 2.15)

  1. Open the Voyager - Stream Stats action, open its Execute C# Code sub-action, replace all of the code with the contents of Voyager_Stream_Stats.cs (v6) and click Compile. Nothing else in the action changes.
  2. Keep Voyager - Community Tracker enabled: it records Twitch subs and resubs, YouTube memberships and milestones, Kick subs and gifted subs.
  3. Keep Voyager running. Its hidden Public website publisher asks Stream Stats once a minute for the last 90 days of subscriber and gifter records and passes them to Missions and Seasons on this PC only. The public site only ever gets goal totals and counts.
  4. Rewards are always Voyager points, never giveaway tickets. Anonymous gifts can't be credited, and a gifted sub also counts as a renewal for the person who receives it.

Verify during your next stream

  1. Check the tracker queue is unpaused and Twitch Live Update is on.
  2. After a few live minutes, check that native Watch time reports saved users and a tracking start date. Keep a known account in chat across two samples; its estimate should increase.
  3. Close the Command Centre for a few minutes while Streamer.bot and the stream stay running. Reopen it and check that the saved total advanced.
  4. After a real sub/resub/gift event, check the relevant tab and platform. Twitch gift totals require a publicly shared cumulative count.
  5. End the stream and confirm that hours stop increasing after the next presence update.

Your saved records

The tracker stores its independent JSON ledger in the persisted global VoyagerCommunityStateV1. It does not change points, buckets, group memberships or giveaway pools. Include Streamer.bot's persisted global data in your normal backup; an action-only export is not the user ledger. The existing points tracker can keep running.

Existing custom user-variable histories remain available through Existing saved user variables. Selecting that mode is optional and is not needed for native tracking. No old history is automatically imported or merged, preventing incompatible units and double counting.
