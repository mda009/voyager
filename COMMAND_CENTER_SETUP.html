1. Copy the update

Use Dashboard pages setup for the files to copy into your existing Voyager_Giveaway folder. Keep your working config.js. For later updates, also keep any stream-command-settings.js you have exported. The new Command Center link is in the sidebar of Giveaway_Control.html.

This addition does not need another change to the Giveaway Engine C# action. Keep your working giveaway queue, chat triggers, pool, claim animation and OBS overlay.

2. Install the Streamer.bot actions

For your existing setup, use the native tracking import instructions. The following is the manual alternative for the read-only stats action. Community tracking also requires the separate tracker in that guide.

  1. Create a dedicated queue named Voyager Stats, with Blocking enabled. Keep it separate from Voyager Giveaways.
  2. Create an enabled action named exactly Voyager - Stream Stats. Assign it to Voyager Stats and leave Concurrent disabled.
  3. Add Twitch → Followers → Get Follower Count.
  4. Add Twitch → Subscribers → Get Subscriber Count.
  5. After those two sub-actions, add Core → C# → Execute C# Code. Replace its entire editor with the contents of Voyager_Stream_Stats.cs, then Compile → Save. Use the same references that compile your existing Voyager actions. The last line reads // End of Voyager Stream Stats v3.

The action only needs those three sub-actions, in that order. It needs no trigger or timer: the page requests it on connection and every 60 seconds. It reads the configured counters, user records, membership counts and saved giveaway summary. It does not send chat, award points, change memberships, create giveaways or draw winners.

If your installation has no Twitch account, omit the two Twitch sub-actions and map other counters; the C# action reports those Twitch totals as unavailable while still reading the other configured sources. Kick user-variable reads require a Streamer.bot build with its Kick integration.

Updating after the Step 2 compile error

If the first version reports CS0012 on line 141 for ITypedList, IBindingList or INotifyCollectionChanged, use the updated Voyager_Stream_Stats.cs v3. Open your existing Voyager - Stream Stats action, edit its Execute C# Code sub-action, select all the old code, and paste the entire updated file. Click Compile, then save after compilation succeeds. The final line must say // End of Voyager Stream Stats v3.

This update replaces the JSON-array LINQ lookup that triggered those errors with an indexed loop. Keep the existing counter sub-actions, queue and configuration. Refresh the Command Center after saving. If a different error remains, send its full compiling-log text.

3. Open and configure the page

  1. Keep Streamer.bot running with its existing WebSocket server started.
  2. Open Voyager_Command_Center.html. It reads your existing config.js. Click Settings if the host, port, password or stats action name differs.
  3. Connect Twitch, YouTube and Kick in Streamer.bot. Monitor your live YouTube broadcast. Viewer data appears when the platform emits its next update; a WebSocket connection alone does not mean every platform is connected.

Optional existing saved user variables

Native mode needs no per-user variable mapping. If you already maintain your own Streamer.bot records, choose Existing saved user variables for that platform; only then are these fields used. Global follower/subscription counter mappings remain separate from the leaderboard mode.

Where do custom variable names come from?

Look at the Set User Variable or C# step in your existing !watchtime, subscription-months or gifted-sub tracker. Copy the exact name, including capitalisation. For a total counter, copy the name from the action that maintains its global variable. A total counter and a per-user leaderboard field are different sources.

Settings fieldExpected stored data
Follower / subscription global variableOne non-negative whole-number channel total. Blank Twitch fields use the native sub-actions.
Watch-time user variableA non-negative numeric value for each user. Select its actual unit; choosing minutes for a seconds-based tracker would overstate time by 60×.
Subscription-months user variableWhole months per user, maintained by your existing subscription tracker.
Gifted-subscription user variableWhole gifted-sub counts per user, maintained by your existing tracker.

Native mode collects live chat-presence estimates and subscription/gift event records directly in Streamer.bot. Twitch has no public API for per-viewer historical watch time. Existing history is not backfilled. The leaderboard reads the top 100 records per platform and shows ten after exclusions; platform accounts remain separate. Gift rankings require a single platform because Twitch's reported totals and observed YouTube/Kick gifts have different historical coverage.

Use the same settings in the browser and OBS

Browsers and OBS can have separate local storage. In Settings, choose Export settings, then put the downloaded stream-command-settings.js beside the Command Center HTML, replacing the template. Refresh the OBS dock. The newer saved settings win. The export omits the WebSocket password; the dock gets that from your existing config.js. Demo settings use separate browser storage and do not replace live settings.

Data freshness and recovery

Viewer counts are received from platform events. The page shows the last update age. After five minutes without a new count, it labels that platform Last reported and excludes it from the current combined audience. A confirmed offline event supplies zero; a missing connection does not. During a disconnect the old figures stay labelled, and the current combined audience becomes unavailable.

Counters and leaderboards are read every 60 seconds while the page is connected. A failed read leaves the last snapshot visible; after 150 seconds it is marked as last received. Stored global counters are only as current as the action maintaining them; manual totals never refresh themselves. Connection retries and heartbeats run independently of the stats queue. The Command Center does not call the Giveaway Engine to refresh data.

The trend chart and activity feed cover this page session and reset when reloaded. Demo mode contains fictional data, is labelled throughout, and never connects to Streamer.bot.

Quick verification

  1. Open the offline demo and try each leaderboard tab, platform filter and goal setting.
  2. Compile the stats action, then open the live page. Compare Twitch followers and active subscriptions against your Twitch dashboard.
  3. While live, compare platform viewer figures after their next update. Monitor all intended YouTube broadcasts.
  4. Follow the live verification in Native Community Setup: wait for consecutive live presence samples, then check the native source status. Subscription and gift rows appear as real events arrive.
  5. Briefly disconnect/reconnect the Command Center; it should show last-received data and recover without triggering any giveaway or chat message.
