New: automatic giveaway announcement

When you click Open entries for an impromptu giveaway or Load & lock pool for a members giveaway, the engine saves the giveaway and submits this message to Twitch, YouTube and Kick through your existing chat accounts:

[Voyager] A giveaway has begun: YOUR GIVEAWAY TITLE

The full title is included, up to the existing 160-character title limit. Keep your platform chat connections active. For YouTube, monitor exactly one broadcast; with none monitored, YouTube is skipped, and with more than one the control page reports that the destination is ambiguous. Bot accounts are preferred with broadcaster fallback.

Install this update: Copy Voyager_Giveaway_Engine.cs and giveaway-control.js into your working giveaway folder. Open the C# file in a text editor and copy the entire file. At the bottom, you should see // End of Voyager Giveaway Engine v7. Reopen or refresh Giveaway_Control.html. Keep the existing references, command triggers, queue and working config.js.

The announcement is attempted once per newly created giveaway. Merely clicking New giveaway, reopening entries, showing the pool, drawing, refreshing or reconnecting does not announce it again. Existing giveaways are not announced retroactively. A failed send does not cancel the giveaway or prevent sends to the other platforms. The control page reports known failures or skipped YouTube announcements. Streamer.bot does not provide delivery receipts for these sends, and interrupted or failed announcements are not automatically retried.

Entry rules: One ticket per platform account, regardless of command repeats or using both aliases. Stable account IDs are used, so two viewers sharing a display name remain distinct. A person's Twitch, YouTube and Kick accounts are separate entries. No membership is required. The command accepts entries only while this impromptu session is open; it does not add viewers to a member-group giveaway.

Reopen entries is available after closing and before the first draw. It keeps existing entries. After any draw, use New giveaway for a fresh pool. All earlier picks stay excluded from rerolls and additional draws in the current session. Entry collection runs in Streamer.bot even if the control page is closed. Streamer.bot and the relevant chat connection must remain running; messages missed during a disconnection cannot be recovered automatically.

Exclusions: Before opening, enter a login such as yourbot, a platform-specific login such as kick:yourbot, or an exact ID such as youtube:id:UCexampleID. Separate entries with commas. User IDs are case-sensitive. ID exclusions are useful for YouTube display names containing spaces. Entries automatically close at the 50,000-account limit. The platform counters show accepted entries, not chat-connection health.

Each new ticket posts a confirmation such as [Voyager] NovaPilot, you're entered! Ticket #0042. Good luck! to the entrant's originating platform only. Repeating either command does not create another ticket or post another confirmation. Twitch and Kick use the configured bot account, with broadcaster fallback. YouTube uses the incoming broadcast ID where available; if the command has no broadcast ID, exactly one broadcast must be monitored to route the reply. Keep the relevant chat-sending account connected and authorized. The detailed board's Ticket Secured label means the entry is saved; it does not imply the platform delivered the chat reply. Claims remain manual: a winner's chat message does not automatically mark the prize claimed.

If a confirmation call throws an error, the entry stays valid and the control page shows a warning. Check Streamer.bot logs and platform connections. Streamer.bot's chat methods do not return delivery receipts, and platform rate limits may delay or prevent messages. Failed or interrupted submissions are not automatically replayed, so refreshing an overlay cannot spam confirmations.

This package handles these draws itself; it does not insert entrants into Tawmae's separate giveaway database or call Tawmae's Pick Winner again.

Run a member-group giveaway

  1. Choose a preset or tick individual groups. Check the entrant list, unique count and equal winning chance.
  2. Enter the prize title. Leave Winner must claim live OFF for Silver/Gold/Platinum/VIP giveaways where presence is not required. Turn it on and set seconds for a claim-required giveaway.
  3. Optionally exclude exact account logins, such as your bot or tracking accounts. These exclusions affect this giveaway only.
  4. Optionally click Show open pool first so viewers can see the live membership list. When ready, click Load & lock pool. The engine reads the selected groups again at that moment and saves a deduplicated snapshot. Any later membership changes apply to your next pool, not this locked one.
  5. Use Export pool if you want to keep the exact entrant list. Click Show pool to display the scrolling members on stream.
  6. Click Draw winner. The result is saved before it is broadcast. Further draws are blocked during the 20-second reveal.
  7. For a no-timer draw, click Confirm winner to record it as confirmed. For a timed draw, manually verify the winner's claim and click Mark claimed before its deadline. Confirmation plays the eight-second congratulations animation, then hides the output.
  8. If needed, click Reroll. The previous winner is marked rerolled and remains excluded. All previously selected accounts are excluded from further draws in the same giveaway, including confirmed winners.
  9. Choose Draw next winner for another prize using the same pool and title, or New giveaway to choose a new title and pool. A new giveaway starts fresh eligibility; history is retained.

Claim timer and replay

The timer begins 30 seconds after a draw: 20 seconds for the reveal plus a 10-second winner hold. At 30 seconds remaining it turns gold; at 10 seconds it turns red. Expiry shows TIME EXPIRED. It never automatically selects another winner. The button is ready for your manual reroll. Claims are not detected from chat; you confirm them in the interface.

Replay winner plays the same selected winner without drawing again. It does not reset the original claim deadline. Hide overlay stops the visible output and its audio; the saved result and claim deadline remain. No-timer reveals finish after 55 seconds. For impromptu giveaways, the compact panel then returns with Drawn status; for member-group giveaways the reveal fades to transparent. The saved winner remains in the control interface until you resolve it.

History and recovery

The pool, picks, confirmation status and the most recent 1,000 history records are held in Streamer.bot's persisted global VoyagerGiveawayStateV1. Refreshing the browser reads that saved state. Export history regularly if you want a long-term archive. Pool and history exports are JSON files and contain no WebSocket password.

If the browser loses connection while drawing, reconnect and check the saved result before trying again. Use Replay winner if the animation was missed. Repeated request IDs are ignored; a stale second control window cannot silently override a newer state. Keep the engine on its dedicated blocking queue.

Starting a new giveaway with an unconfirmed pick records it as not_confirmed. It does not remove that account from a Streamer.bot group. This package does not change group memberships, points, subscription status or Voyager tier tenure.
