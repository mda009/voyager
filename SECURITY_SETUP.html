MDA009 / VOYAGER SECURITY

Account monitoring.
Evidence before action.

Add this page to your existing Voyager Command Centre. It monitors Twitch chat accounts and the Twitch entrants in your current Voyager giveaway, keeps sourced reports and records your reviews. It never sends chat, bans users, changes points or edits giveaway eligibility.

What it can establish

SignalMeaning
Chat presenceAccounts in Streamer.bot's latest Twitch presence sample. Twitch exposes chat connections, not a complete identity list of everyone watching video. Anonymous viewers cannot be identified.
Twitch suspicious-user signalsObserved restriction/monitoring changes and suspicious messages. Ban-evasion evaluation and shared-ban counts are captured when the trigger supplies those arguments. Missing detail is left unknown; check Twitch Mod View.
Channel bansBan and unban events observed in your own channel after installation. This is not a full existing ban-list import or a site-wide suspension check. A ban does not prove someone is a bot.
External reportsTwitch Insights bot-list matches, or reports you import with source/date/evidence. A report can be wrong or outdated; utility bots can be legitimate. “Confirmed by you” is only assigned through an explicit case review.
Possible alts / coordinated entriesCombined account-creation, entry-time and login/chat patterns. They suggest accounts worth reviewing; they cannot establish common ownership. The page cannot access private IP, device, phone or email information.
Compromised / cloned accountsSourced reports, your evidence notes and similar-login checks. Account age, absence from a lookup, shared spelling or an old bot-list match do not prove compromise or impersonation.

2. Import the Security action

  1. In Streamer.bot click Import and select Voyager_Security_Install.sb. If the dialog expects an import string, open that file in Notepad, copy its entire contents and paste them there.
  2. Import the single Voyager - Security Monitor action and the Voyager Security queue. No existing action is replaced by this import.
  3. Open the action's Execute C# Code sub-action, click Compile, then Save when compilation succeeds. The last line must read // End of Voyager Security Monitor v1.
  4. Check the action is enabled, assigned to the unpaused Voyager Security queue, with Blocking ON and Concurrent OFF. Keep only one enabled copy.

The import includes the standard references from your supplied Stream Stats and Points actions: mscorlib, System, System.Core and Newtonsoft.Json. It does not need Tawmae. C# compilation cannot be performed in this environment; if your installation reports an error, copy the complete compile-log text.

4. Check presence and open the page

  1. In Platforms → Twitch → Settings → Present Viewers, turn Live Update ON. Use the one-minute interval from the native community-tracking setup if already configured. Security itself can accept the normal 1–10-minute interval; changing it also changes how often your existing points action receives that event.
  2. Open Voyager_Security.html, or choose Security in the Command Centre sidebar. Your existing WebSocket connection is reused. Use Connection for a session-only override if necessary.
  3. Wait for the next Present Viewers sample. The page refreshes its saved snapshot every 15 seconds while open.
  4. Choose All tracked accounts if the Needs review filter is empty. Use Look up account for a particular Twitch login.

The monitor operates while Streamer.bot runs, even with this page closed. It checks up to two recently present accounts or current entrants per presence tick for account creation dates; unknown profiles remain explicitly unknown. A selected profile can be refreshed manually, with a one-minute cooldown. Lookups do not create fake presence records.

Use this as a private operator page or OBS custom browser dock, not an on-stream browser source: it contains moderation observations and your notes. In OBS choose Docks → Custom Browser Docks and use the file URL for Voyager_Security.html in your working folder.

5. Connect external reports

Twitch Insights is enabled by default. The monitor downloads the public list at its first presence tick and then no more than once every six hours; Sources & reports → Refresh bot list now can retry with a one-minute cooldown. It fetches the whole list and compares logins locally; it does not upload your viewers. Availability and format can change. A failed refresh retains the last cache and displays an error. Matches older than seven days become information-only.

For other websites or moderator evidence, download security-report-template.csv, add your reviewed records, then choose that file in Sources & reports. JSON arrays using the same field names are also supported. Review the preview and click Import reviewed reports.

ColumnRequired value
id / loginA Twitch numeric ID or exact login; an ID is preferable because logins can change. If an ID is supplied, matching uses that ID only.
categorybot, banned, compromised, impersonation, alt or abuse.
sourceThe website or reviewer that made the report.
urlOptional http/https evidence link. The monitor does not fetch arbitrary URLs.
observedAtObservation date, ideally ISO format, for example 2026-10-19T06:00:00Z.
evidenceA specific supporting note, between 5 and 1,000 characters.

Imports are capped at 1,000 rows / 1 MB each and 5,000 stored reports. Duplicate source/date/account/category rows are ignored. Imported claims never become automatic confirmations. Reports older than 90 days become information-only. The page shows the latest 100 imported reports for review/removal.

6. Review an account

  1. Click an account name. Read the source, timestamp and reason for each signal, then check its Twitch profile or Mod View as appropriate.
  2. Mark it Watchlist, Trusted, Cleared by you, or one of the Confirmed by you categories. Add an evidence/reason note.
  3. For possible relationships, enter related observed Twitch IDs. Confirmed alt findings require another observed ID and your supporting note. No algorithm can make this confirmation for you.
  4. Save the review. It is persisted in Streamer.bot with an audit entry. A changed case in another dock must be refreshed before saving over it.
  5. If you decide an account should be excluded from a future giveaway, use Copy giveaway exclusion, then paste the exact token into Giveaway Control's exclusions before loading a new pool. Copying or reviewing does not change a locked pool or remove an accepted entry.

Trusted/cleared accounts suppress local age, message-pattern and lookalike heuristics. External source matches remain visible as information, and Twitch moderation signals remain visible for review. A missing flag is not a guarantee that an account is genuine.

How the rules work

RuleThreshold / interpretation
New accountUnder seven days old: information only. Newness alone is not flagged as abuse.
Entry-command burstAt least five !ticket / !enter attempts within 60 seconds while a chat giveaway is open. Attempts do not mean extra accepted tickets; the existing draw engine still deduplicates by account.
Repeated chatAt least four matching non-command messages of at least 20 characters within 60 seconds. Common giveaway commands are excluded. Repetition can be legitimate and needs context.
Similar protected loginA simple spelling check against the protected names in Sources. It is not a full Unicode impersonation detector or identity match.
Possible account linkBoth accounts under 30 days old, created within ten minutes, entered the current giveaway within 15 seconds, plus similar login patterns OR the same longer non-command chat text posted within 30 seconds. Common !ticket/!enter messages, silence and coincident presence alone never create links. Maximum 200 candidates; the page shows when this cap is reached.
Priority reviewAn operator-confirmed finding, observed channel ban or Twitch “likely” evasion signal. These are review priorities, not calculated fraud probabilities.

Data retention and backup

The independent persisted global VoyagerSecurityStateV1 holds observed accounts, reviews, reports and the latest 1,000 review/source audit entries. VoyagerSecurityFeedV1 holds the public bot-list cache. Back up Streamer.bot's persisted globals; an action-only export does not contain these records.

Per account, the monitor retains the latest 20 message fingerprints (not chat text), 30 entry attempts, 20 moderation/burst events, 10 previous logins and a 100-message-ID deduplication window. Fingerprints and attempts expire after seven days. Inactive unreviewed accounts expire after 30 days unless in the loaded pool or related to another case. Reviewed cases remain until you change their status and they later expire. At 10,000 retained accounts, new collection becomes partial and reports a capacity warning. This is an operational review log, not a complete forensic archive.

Monitoring starts after installation. Previously banned users, historical behaviour and previously compromised accounts are not automatically reconstructed. Native test and shared-chat guest events are ignored.

Quick verification

  1. Open Preview Security and inspect the clearly fictional cases. Try filters and a sample review.
  2. Compile the live action and verify the seven triggers. Open the live Security page and confirm the connection.
  3. After a presence tick, verify your known chat accounts appear. Compare the latest sample with Twitch's Users in Chat list, allowing for update delays.
  4. Send one ordinary message from a known test account. Its observed message count should increase, with no review signal merely for chatting or staying silent.
  5. Open a test giveaway through your existing control and enter once. Security should show the account in the current pool after the next read. Verify the existing overlay and entry confirmation still work.
  6. Check Sources & reports for a bot-list fetch time or a clear fetch error. A failure must not clear previous matches.
  7. Save a review, refresh the page, then close/reopen it. The review and audit entry should remain.

JavaScript logic and DOM interactions are tested locally. This environment does not provide Streamer.bot's C# compiler or your authenticated Twitch session; compile and verify native events on the streaming PC. Browser rendering was not available for this update.
