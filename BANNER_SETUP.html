Already using the Voyager banner?

For this appearance update, follow BANNER_STYLE_UPDATE.txt. Copy the four listed webpage files and keep the bundled fonts, then refresh the banner OBS source and the Stream banner control page. No Streamer.bot import or C# compilation is needed. The full installation steps below are for a banner that has not been installed yet.

What changes after setup?

Edit messages and style in Voyager → Stream banner, then click Publish to OBS. Connected browser sources update without editing HTML or manually refreshing OBS. The saved banner lives in Streamer.bot and remains available when the control page is closed.

Show/hide and pause/resume immediately change the published banner. They leave unfinished draft text alone. No Twitch chat messages are sent.

1. Copy the updated files

  1. Back up your current Voyager folder and existing ticker HTML, then extract the new ZIP.
  2. Copy the new Voyager_Banner_Control.html, Voyager_Banner_Overlay.html, Voyager_Banner.cs, Voyager_Banner_Install.sb, BANNER_SETUP.html and every file beginning banner- into your working Voyager folder.
  3. Copy the updated Voyager_Command_Center.html, Giveaway_Control.html, Voyager_Points.html and Voyager_Security.html to add the new navigation link. The package also includes an updated Preview_Voyager_Control.html.
  4. Keep your working config.js and existing settings/data files. Keep giveaway-connection.js, stream-command.css, voyager-brand.css and the brand-assets folder beside these files. The new ticker uses the bundled Rajdhani font.

You can copy the full updated folder over your working copy instead, but retain your own config.js, stream-command-settings.js, stream-home-data.js and twitch-analytics-data.js. Your original uploaded ticker is retained unchanged as a reference; OBS will use the new connected overlay after step 3.

2. Import one Streamer.bot action

  1. In Streamer.bot, click Import and load Voyager_Banner_Install.sb.
  2. Import the Voyager - Banner action and the Voyager Banner queue. This is a new independent action; do not replace your giveaway, points, stats or community actions.
  3. Confirm the action is enabled, Concurrent is off, and its queue is Voyager Banner. The queue must be Blocking and unpaused.
  4. Open its Execute C# Code sub-action, click Compile, then save. The import includes assembly references copied from your supplied setup. No manual DLL search should be needed. If compilation fails, send the full error text.
  5. No triggers or timers are needed. The control and OBS pages call this action through the existing WebSocket connection. Keep exactly one enabled action named Voyager - Banner.
  6. Open Voyager_Banner_Control.html from the new Stream banner navigation link. It should show Connected and your original messages. If needed, use Connection to enter the same local host/port/password as your existing setup. Overrides here apply only to this control page; OBS still reads config.js.

3. Point your existing OBS ticker source at the new HTML

  1. In OBS, right-click the browser source currently loading futuristic_ticker(1).html (or your original ticker filename), then select Properties.
  2. Keep Local file selected. Browse to Voyager_Banner_Overlay.html inside your working Voyager folder.
  3. Set the source width to your OBS canvas width and its height to 120. The visible strip defaults to 56 px high and sits at the bottom of this transparent source. This allows room for larger text and banner-height adjustments.
  4. For a 1920 × 1080 canvas, use a 1920 × 120 browser source. With no crop and scale 1.0, position it at X 0, Y 960. If your canvas differs, use X 0, Y = canvas height − 120. Existing source cropping or scaling may need resetting in Transform → Edit Transform.
  5. Click Refresh cache of current page once after changing the file. Keep the source visible for the first connection. You should see your messages scroll in the translucent rounded strip.

The overlay is fully transparent outside the strip; the strip itself has a light translucent background and a 16 px inset on each side. Do not use Voyager_Banner_Control.html as the on-stream source; that file is the editor. Keep the optional default transparent OBS custom CSS; remove old CSS that overrides this banner’s height, colours or animation.

4. Update the banner during a stream

  1. Open Stream banner in Voyager. You can also add Voyager_Banner_Control.html as a separate OBS custom browser dock using the same local-file URL method as your existing Voyager dock.
  2. Enter one message per line. Blank lines are ignored. Messages loop in the order shown. Text is plain text; HTML tags and scripts do not run.
  3. Adjust scroll speed, text size, strip height, panel tint strength, colours, spacing, separator, uppercase and scanlines. Speed is pixels per second: larger numbers move faster. Tint strength 100% matches the giveaway panel’s 48%–38% background opacity; 0% removes the panel tint, with borders and text still visible. Existing saved tint values now use this transparent range.
  4. Inspect Draft preview. It always scrolls visibly so you can review text even if your live banner is hidden or paused. Invalid settings show an error and keep the last valid preview.
  5. Click Publish to OBS. This saves text and style while retaining the published visibility and pause state. A hidden banner stays hidden until you press Show banner.
  6. Use Published preview to inspect the saved version. “Published” means Streamer.bot accepted the settings; it does not prove that OBS is showing the correct source or scene.

You can close the editor after publishing. Unpublished drafts save in the current browser only; different browsers and OBS docks have separate draft storage. Published settings are shared through Streamer.bot.

Show, hide and pause

ControlEffect
Hide / Show bannerChanges the saved strip’s visibility in all connected overlays. Does not publish draft text.
Pause / Resume scrollStops or resumes scrolling at its current position. If text, size or spacing changes, the animation restarts with the new content.
Load published banner into editorReplaces the editor draft with the current saved banner. Copy any unfinished draft text you want to keep first.
Load original text & style into draftRestores the supplied ticker’s starter copy in the editor only. Publish is still required.

If Streamer.bot disconnects, an already loaded overlay continues showing its last received settings. Hide/pause changes cannot reach a disconnected source; use the OBS source eye icon if you need to remove it immediately.

Saved state and validation

Published text and appearance are stored in the persisted global VoyagerBannerStateV1. Include persisted globals in your Streamer.bot backups. A version check prevents older drafts silently replacing newer publications; reconnect only reads saved state. The local OBS cache is a fallback, not the shared source of truth.

This integration uses the custom-message mode from your supplied file. Its RSS option was disabled, and this version does not fetch an RSS feed.
