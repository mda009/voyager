The current package uses three dashboard pages. First follow Dashboard pages setup to copy all required webpage files. Then follow the action-specific steps below if those actions are not already installed.

MDA009 / VOYAGER CONTROL

Automatic external data.

The Reporting dashboard checks TwitchTracker and TwitchMetrics whenever it connects after opening or reloading the page, then every 30 minutes while the page stays open. The last good figures remain visible when a provider is unavailable.

Update your existing installation

  1. Close the Reporting page and its OBS dock. Extract the new ZIP to a temporary folder.
  2. Copy the files listed below into your existing Voyager_Giveaway folder, accepting replacement for these files. Keep your own config.js, stream-command-settings.js, stream-home-data.js and twitch-analytics-data.js.
  3. Open Streamer.bot and choose Import. Drag Voyager_External_Analytics_Install.sb into the import window and import the included action and queue. This adds one action named Voyager - External Analytics in the Voyager External Analytics queue. Import it only once.
  4. Open the action's Execute C# Code sub-action. Click Find Refs, then Save and Compile. Confirm it compiles. Leave the action enabled, Concurrent off, and its dedicated queue running. It needs no triggers, chat commands or Streamer.bot timers; the page requests the reads.
  5. Keep Streamer.bot running with its WebSocket server enabled. Open Voyager_Reporting.html, or refresh the existing OBS dock. Your saved Connection settings are reused.
  6. Under External data, allow up to 75 seconds for the initial check. Both source cards should show a successful retrieval time, or a specific error. Use Refresh external data to retry after correcting setup. Reloading the page also starts a check.

What updates

SourcePublic information
TwitchTrackerIts documented rolling 30-day channel summary: average and peak viewers, hours watched, streamed time, total followers, follower change and overall worldwide rank. The API does not provide exact period timestamps, so the page labels this as a rolling summary retrieved at a stated time.
TwitchMetricsThe dates and figures in its public monthly performance section and FAQ, category ranking when present, and the recent stream rows visible on the public overview. A partial stream log is labelled as partial; it is not treated as complete history.

The providers use their own collection and update schedules and can report different values. Voyager keeps their snapshots separate. The latest reporting date is selected automatically after load, preferring TwitchTracker when both dates match. Choosing an older period keeps that selection during subsequent automatic checks. Worldwide rank remains clearly attributed to TwitchTracker.

Refresh behaviour

  • Page load, reload and WebSocket reconnection request a source check.
  • A check runs every 30 minutes while the page remains open. Returning to a suspended page checks when overdue.
  • The Refresh external data button and the main Refresh button also request a check. Only one check runs at a time per page.
  • Streamer.bot shares a five-minute successful-response cache across open docks and browser windows. Rapid reloads use that recent result with its original retrieval time.
  • A failed provider has a 15-minute retry cooldown, or a longer server-specified retry time. Other providers can still update. Errors and the last successful retrieval time are displayed separately.
  • Source retrieval time means Voyager received readable public data; it does not claim the provider has just recalculated its figures.
  • Up to 400 source/date snapshots and 500 stream rows are kept. Same-source, same-day refreshes replace that snapshot instead of adding duplicates. Export the Home JSON if you want a longer archive.
  • The CSV reporting windows remain Previous 30 days, 14 days, 7 days and Latest stream. Uploaded CSV reports, private Twitch analytics, live counters and community leaderboards are separate.

If a source does not update

MessageAction
Import and enable one actionCheck there is exactly one enabled Voyager - External Analytics action. After importing or enabling it, press Refresh external data.
No external analytics responseOpen the new action, use Find Refs and Save and Compile, and check its dedicated queue is running. Existing giveaways and points use their own queues.
Missing assembly or System.dll errorUse Find Refs in the code editor. If an imported reference path is invalid, remove that invalid reference and use Find Refs again. Newtonsoft.Json comes with Streamer.bot. Do not download replacement DLL files from random sites.
HTTP 403, 429, challenge, timeout or changed formatThe provider did not supply readable public data. The previous successful snapshot stays visible. Wait for the indicated retry time and use Refresh external data. You can still open the source links and use Edit saved performance. No paid or protected endpoint is accessed.
DisconnectedCheck Streamer.bot's WebSocket server and the Home Connection settings. The page reconnects automatically after a transport interruption.
History updated while editor openClose and reopen Edit saved performance to load the automatic refresh before saving manual edits. Copy any unsaved manual edits before closing.

Browser and OBS storage can be separate. Each loads the current public summary through the same Streamer.bot action; your older manual history remains in the browser or dock where it was saved.
